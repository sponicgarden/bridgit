Use the tools you enable to help an agent understand your world and reach you on your phone.

Bridgit requires Android 14 or later, a private Tailscale connection and an agent whose HTTP or MCP tools can reach the phone. This guide distinguishes implemented tools from future appliance ideas.

App screens below were captured from 1.5.4; the fictional interaction example is labeled separately as a 1.6 development preview. The 1.6.0 API reference documents additional capabilities, with partial device acceptance.

1. Connect an agent you approve

On a phone with the Bridgit preview installed, connect the phone and agent host through your Tailscale network. Add a named agent and use the pairing prompt generated by the app. It contains the phone address and that agent’s key; keep it in the agent’s secret store.

Hosted chat products need a connector that can reach the private address. A model or subscription alone is not enough. Check the connection guide.

2. Choose its tools and access

Enable the features you want, such as camera, microphone, screenshots, photos, location or audio playback, and grant their Android permissions. The 1.6.0 implementation also adds files, sensors, phone controls and per-agent capability grants. New switches start off; review grants for older unrestricted agents.

Snapshots require an unlocked phone. Screen sharing, notification access, app usage and Health Connect have separate Android approval requirements. SMS, contacts, calendar and calls remain exploratory.

3. Ask for a useful action

“Show me what’s on the workbench.” “Read the next step aloud.” “Show me the options and ask which one I want.” Your agent supplies the reasoning and follow-through; Bridgit supplies the enabled device tools, phone interface and activity record.

Questions, choices, interactive cards and live text give an agent a way to reach you. Replying to a card is not a blanket approval to book, buy or send something; your agent must handle each real action under your authorization.

4. Try an agent-guided session

City tour is an implemented ready-made session: pick a tour and agent, share location, heading and photos you take, and hear the agent’s commentary. You can pause or end the session. Agent-managed workflows can also combine the documented tools while that agent is running.

A general appliance runtime is still in development. The proposed runtime would let an agent describe a workflow and let you review its permissions, recipients and duration before activation. It is not a general feature of the current app. Live camera streaming and voice-triggered help are also future ideas.

5. Pause, review or revoke access

Use the listener control or Quick Settings tile to pause access. Review requests and results in Activity. Remove or rotate an agent’s key when its job is done. Feature switches and grants restrict access; they do not guarantee an agent’s judgment or recall content it already received.

Newer implementations cancel guarded operations after relevant access changes. Cancellation and timed setting restoration remain subject to Android and the operation involved. Read the data-control details.

Private app assistance

The local control build adds a reviewable session for selected apps: observe a fresh screen, propose a bounded action, approve it on the phone, and inspect the resulting state. A successful input dispatch is not proof that a booking, message or payment completed. The existing v1 tools remain available; new app control and native workflows are separate from the published 1.6.0 download. See the development build’s scope.
