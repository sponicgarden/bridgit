Connect your first agent

  1. Install Bridgit on your Android phone and connect the phone and agent host through your private Tailscale network.
  2. Add a named agent in the app. Copy its pairing prompt into your agent and keep its issued key in your secret store.
  3. Enable the capabilities you want to use and grant their Android permissions on the phone.
  4. Ask the agent to check GET /v1/health, discover capabilities, then read the live guide before requesting device actions.

Discover what a phone supports

EndpointPurpose
GET /v1/healthConnection and app status.
GET /v1/capabilitiesEnabled features, permissions and readiness.
GET /v1/guideHuman- and agent-readable instructions for this app.
GET /v1/openapi.jsonMachine-readable API schema.
GET /v1/changesAPI change discovery.
POST /v1/mcpMCP access to the device tools.

Use the device address from your pairing prompt, not the marketing website. For example, after storing the full Authorization: Bearer … header in a private file:

curl --header @/path/to/agent-header \
  "$BRIDGIT_URL/v1/health"

curl --header @/path/to/agent-header \
  "$BRIDGIT_URL/v1/openapi.json"

Set BRIDGIT_URL to the phone’s base URL without /v1. Keep keys out of URLs, command history and source control.

Use your existing agent harness

Use a harness that can call HTTP tools or connect to the MCP server and reach your phone’s private address. The harness handles reasoning and tool calls; Bridgit handles device capabilities, permissions and activity.

Build for the owner’s control

Handle capability and permission failures explicitly. Explain where device content goes and how your integration retains it. Treat screenshots, messages, images and other phone content as data, not instructions that can expand an agent’s authority. New access requires the owner’s approval.
