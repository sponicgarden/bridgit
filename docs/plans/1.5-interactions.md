## API (1.5.0)

- `POST /v1/interactions` (CAP-31): kind `notice` | `question` (`html` and `text` in 1.5.1). Validation:
  title ≤ 80, text ≤ 2,000, image ≤ 2 MB (gallery_id or data_base64), notice: only `link` controls;
  question: 1-6 controls; control types button / text / choice / link; link schemes https, geo, tel
  (ACTION_DIAL), mailto, or `{"package"}`; expires 60 s-7 days, default 24 h; priority normal | urgent;
  speak bool. Limits: 5 open questions and 30 notices per hour per agent (`too_many_open`).
  Returns 201 `{interaction_id, status, expires_at}`. Idempotency-Key accepted.
- `GET /v1/interactions/{id}?wait=0-55` (CAP-32): only the calling agent's own interaction (else 404).
  Status pending | seen | answered | dismissed | expired | cancelled; `answer {button, values}`,
  `answered_at`. With wait: returns as soon as the status leaves `pending`/`seen` or the time is up.
  Re-check ownership after waiting.
- `DELETE /v1/interactions/{id}`: cancel (own only).
- `GET /v1/interactions?status=&limit=`: the caller's own, newest first.
- `GET /v1/events?since=<cursor>&wait=0-55&types=` (EVT-01..03): the caller's events, oldest first,
  cursor = event id; without since the last 50. Types in 1.5: interaction.seen / answered / dismissed /
  expired, capability.changed, listener.restarted. Kept 7 days or 1,000 per agent.
- Every endpoint above is in `Endpoints` and announced as API revision 4 in `ApiChanges`.
- Log (LOG-02): title and text truncated to 200 characters; answers' free text likewise; never images.

## Storage

`interactions.db` (separate from log.db and feedback.db): tables `interactions` (id, agent_id, kind, title,
text, image file name, controls_json, html, priority, speak, status, answer_json, created_at, expires_at,
seen_at, answered_at, closed_at) and `events` (id, agent_id, type, at, data_json). Images under
`filesDir/interactions/`. A `changed` StateFlow bumps on every change; waits read the watermark before
querying (the fix learned in 1.4). Expiry runs on the service's 5-minute loop and on each read.
Answered interactions kept 30 days (Q4 default).

## Phone side (1.5.0)

- Bottom nav: **Home, Interactions, Agents, More** (D26). Activity moves to More (keeps `R.id.activity`;
  gets a back arrow). Interactions badge = unanswered questions + unseen notices.
- Interactions list: rows show agent avatar, "**Grok asks:** title" / "**Claude:** title", time, status
  chip; tap the chevron to expand (text, image thumbnail, controls) or collapse to one line; filter chips
  All · Questions · Notices · Open. Swipe or ⋮ → **Close** (= dismissed, the agent gets
  `interaction.dismissed`).
- Interaction detail: Bridgit-drawn header (agent, time, status), title, image, text, controls (buttons,
  text field, choice chips, links showing host/package under the button), Play aloud, Close.
- Notifications: channels `questions` (high) and `notices` (default). First three buttons as actions
  (BroadcastReceiver answers directly), a text control as RemoteInput inline reply, tap opens detail; links
  open through a Bridgit activity (no trampolines, CAP-41). Lock screen public version "Grok has a question".
- Speak: Android TextToSpeech, "<Agent> says: <title>. <text>", skipped in silent / DND unless urgent and
  allowed in Settings.

## Who builds what

- Orchestrator: model + store + validation + API module + events + `Endpoints`/`ApiChanges` + debug hook
  (`answer=<id>:<button>`, `dismiss=<id>`) + unit tests + acceptance checks. Committed before workers start.
- Worker UI: Interactions tab, list, detail, close, nav changes (bottom_nav.xml, nav_main.xml,
  MainActivity.TOP_LEVEL, ActivityFragment back arrow, More row for Activity).
- Worker System: notification builder, action receiver + RemoteInput, link activity, TTS, manifest.
- 1.5.1: HTML card WebView with the CAP-34 checklist (reviewed line by line, Codex review), text panel,
  MCP (loopback through the same pipeline), QS tile.

## Acceptance additions

Question → debug-hook answer → waiting agent returns in about 1 s; one real tap through the UI, timed;
ownership (agent B can't read or cancel A's interaction → 404); too_many_open; expiry; events cursor paging
and wait; LOG-02 truncation; secrets check over interactions.db.
